1. 粘贴批量改动证明

叶节点 = SHA-256(00 ‖ 叶摘要)，内部节点 = SHA-256(01 ‖ 左摘要 ‖ 右摘要)。叶必须严格按 256 位键路径升序排列； 共享兄弟节点以 depth（节点层级 1..256）与 prefix （该层级等长 0/1 前缀）定位。服务会同时自底向上重建旧树与新树，不采信提交方摘要。

填写许可后，服务仍先完成旧/新根与共享证明的同步复算；双根有效后，才把每个变更键与其所有 前缀匹配许可组成容量约束——任一变更键无候选许可、或全部键无法各占用一次许可额度，整批拒绝。 嵌套/重叠许可不按输入顺序贪心分配，而是在全部可行分配中给出「键路径升序 × 许可标识字典序最小」 的唯一稳定见证，并返回逐键命中前缀与各许可的已用/未用额度。留空则保持原有核验请求与响应。 想观察拒绝：点「容量不足变体」载入后提交，真实 API 将返回 license_capacity。
